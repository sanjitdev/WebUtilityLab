## Story

As a **user landing on the empty-state of CSV Rescue for the first time**,

I want **the "Try the example" button to load a small sample CSV without making a network request**,

so that **I can see what the tool does without uploading my own file, AND the page stays consistent with the Privacy Baseline (zero network calls after page load — the sample is bundled inline)**. The deployed bundle never reaches out for the fixture; the fixture source lives in `public/examples/sample.csv` for the maintainer's offline review and for E08's golden-test fixture set, but the build-time script (`scripts/inline-example.mjs`) reads it once and bakes it into the JS bundle as a string constant.

## Acceptance Criteria

### AC24a — `public/examples/sample.csv` fixture source

1. **A new fixture `public/examples/sample.csv` is committed.** The fixture is a small, deterministic CSV (8-12 rows, 4-6 columns) that demonstrates the tool's value: a header row + data rows with one or two intentional quirks (a missing value, an inconsistent categorical, an invalid email). E08's fixture set will reuse it for golden tests. The fixture is plain UTF-8, CRLF-terminated rows, with a header row. No BOM (per the S03.5 lede "UTF-8, with or without a BOM"; the example is the simpler form).
2. **The fixture is the SINGLE source of truth.** `public/examples/sample.csv` is read by `scripts/inline-example.mjs` at build time. Any other copy of the CSV in the source tree is forbidden (a regression check guards against duplication).
3. **The fixture is small enough to ship inline without bloating the bundle.** Budget: 4 KB raw (gzipped: ~1 KB). A larger fixture would fail the AC24f `check:bundle` pin.

### AC24b — `scripts/inline-example.mjs` build-time inliner

4. **A new script `scripts/inline-example.mjs` reads `public/examples/sample.csv` and writes `src/lib/example-csv.generated.ts`.** The generated module exports three constants:
   ```ts
   export const SAMPLE_CSV: string = "<contents of sample.csv, escaped for TypeScript string literal>";
   export const SAMPLE_CSV_FILENAME: string = 'sample.csv';
   export const SAMPLE_CSV_MIME: string = 'text/csv';
   ```
   The string is escaped (backslashes, newlines, quotes) so it round-trips through TypeScript's parser unchanged. A `console.log` line prints `[inline-example] wrote src/lib/example-csv.generated.ts · <bytes> bytes · <rows> rows` for the build log.
5. **The script is idempotent.** Running it twice in a row produces byte-identical output (the generated module's contents are deterministic — no timestamps, no random suffixes).
6. **The script is invoked from `npm run build` AND from a pre-test hook.** The `package.json` `build` script chains: `vite build` runs AFTER `inline-example`. The `test` script runs `inline-example` FIRST so the generated module exists when tests import it. A regression that runs `vite build` without `inline-example` first would produce a bundle with no example CSV; the AC24d pin catches this.
7. **The script is invoked from the prebuild hook too.** `npm run dev` should also have the generated module available (the dev server may import it for HMR). The `dev` script chains `inline-example` too.
8. **The script has a tiny test of its own.** A unit test pins the script's escape behavior (a CSV containing a backslash, a double-quote, a newline, and a CRLF must round-trip through `inline-example.mjs` unchanged). The test lives in `tests/inline-example.test.ts`.

### AC24c — `src/lib/example-csv.generated.ts` is generated, not hand-authored

9. **The file `src/lib/example-csv.generated.ts` is added to `.gitignore`.** It is generated; committing it would create merge-conflict risk (a contributor regenerating the module from a slightly-different fixture version would create a noisy diff). The file EXISTS in the working tree (after running the build/test script) so it can be imported.
10. **The generated module's content matches the fixture exactly.** A test reads both `public/examples/sample.csv` and `src/lib/example-csv.generated.ts`, extracts the string constant from the generated module, and asserts byte-equality.
11. **The generated module is exported via `SAMPLE_CSV`, `SAMPLE_CSV_FILENAME`, `SAMPLE_CSV_MIME`.** The names match the App.svelte consumer.

### AC24d — `src/lib/example-csv.ts` helper

12. **A new module `src/lib/example-csv.ts` exports `makeExampleFile(): File`.** The function constructs an in-memory `File` via `new File([SAMPLE_CSV], SAMPLE_CSV_FILENAME, { type: SAMPLE_CSV_MIME })`. No network IO. No `fetch`. No `URL.createObjectURL`. The `File` is a uniform in-memory representation, identical in shape to a real drop.
13. **`makeExampleFile()` is the ONLY public surface.** The internal `SAMPLE_CSV` constant is not re-exported; consumers go through `makeExampleFile()` so the string is encapsulated inside the File object.
14. **The module is token-disciplined (AD-8): no hex literals.** The helper imports the constants from `./example-csv.generated` and constructs the File; no styling happens here.

### AC24e — App.svelte wires the "Try the example" button

15. **The "Try the example" button loses `disabled` and `aria-disabled="true"`.** The button becomes a real `<button type="button" onclick={handleTryExample}>Try the example</button>`. The `disabled` attribute is REMOVED (so the user can click AND tab to it); the `aria-disabled` attribute is REMOVED (no longer needed).
16. **A new `handleTryExample` function in App.svelte calls `makeExampleFile()` and dispatches to the reducer.** The handler shape mirrors `handleAccept`'s drop branch but is shorter — it doesn't announce via aria-live (the announcement comes from the reducer's `accept` dispatch which routes through `handleAccept` after the button's on-click triggers a synthetic accept). The handler either (a) calls `handleAccept({ kind: 'drop', file: makeExampleFile() })` directly (simpler), OR (b) calls `reducer.dispatch({ kind: 'accept', source: { kind: 'drop', file: makeExampleFile() } })` followed by the same aria-live announcement as `handleAccept`. The S03.8 spec author picks the form that minimizes code duplication: option (a) is preferred — `handleTryExample` is a one-liner that calls `handleAccept`.
17. **The S03.5 affordance docblock is updated.** App.svelte's template comment block (lines 142-156 of the current source) describes the "Try the example" button. S03.8 rewrites the comment to past-tense and to reference the new wiring.

### AC24f — Tests + Privacy Baseline

18. **A new test file `tests/dropzone-example.test.ts` pins AC24a-AC24e.** Test count target: 30+ new assertions. Specifically:
    - AC24a: `public/examples/sample.csv` exists; fixture is non-empty; fixture is parseable as CSV (no BOM, CRLF or LF terminators, at least 2 rows).
    - AC24b: `scripts/inline-example.mjs` exists and is invokable; running it twice produces byte-identical output; the escape logic round-trips a tricky CSV (backslash, quote, newline, CRLF).
    - AC24c: the generated module exists (after the script runs); `SAMPLE_CSV` matches the fixture byte-for-byte; `SAMPLE_CSV_FILENAME === 'sample.csv'`; `SAMPLE_CSV_MIME === 'text/csv'`.
    - AC24d: `makeExampleFile()` returns a `File` instance with name `'sample.csv'`, type `'text/csv'`, and `size === SAMPLE_CSV.length`.
    - AC24e: App.svelte's "Try the example" button: `disabled` REMOVED, `aria-disabled` REMOVED, `onclick` handler BOUND. The handler calls `handleAccept({ kind: 'drop', file: makeExampleFile() })`.
19. **The S03.5 inverted boundary pin in `tests/dropzone-empty-state.test.ts` AC21c is FLIPPED.** The current pins assert `disabled` is present, `aria-disabled` is present, no click handler. S03.8 flips them to the negatives: `disabled` is absent, `aria-disabled` is absent, `onclick` is present.
20. **Privacy Baseline (PRD FR-23): zero `fetch` / `XMLHttpRequest` / network primitives introduced.** The new files (`public/examples/sample.csv`, `scripts/inline-example.mjs`, `src/lib/example-csv.ts`, `src/lib/example-csv.generated.ts`) contain no network calls. The test pin (in `tests/dropzone-example.test.ts`) scans each new file with the S03.7 forbidden-patterns regex (the same list — `fetch`, `XMLHttpRequest`, `EventSource`, `WebSocket`, `sendBeacon`, `new Function`, `eval`, dynamic `import()`, `FileReader`, `readAsText`, `readAsArrayBuffer`, `navigator.clipboard`).
21. **`dist/` must NOT carry a `examples/sample.csv` URL.** The deployed HTML/JS bundle does not fetch the fixture; it's bundled inline. A test in `tests/dropzone-example.test.ts` greps the dist output for the literal `examples/sample.csv` — must be absent.
22. **AD-8: zero hex literals.** The new files (`example-csv.ts`, `example-csv.generated.ts`, `inline-example.mjs`) contain no hex color literals. The S03.7 hex-literal pin is extended to the new files.
23. **Bundle budget preserved.** The fixture is small enough that adding it to the bundle stays well under the 200 KB gzipped budget. The post-S03.8 `npm run check:bundle` shows the same or smaller total than S03.7 (the fixture is ~1 KB gzipped; the inliner + helper add ~0.5 KB gzipped; total delta ~1.5 KB gzipped).

## Cross-story contract notes

- **S03.5 inverted boundary pins.** S03.8 flips the AC21c pins in `tests/dropzone-empty-state.test.ts` from positive (disabled + aria-disabled + no handler) to negative (no disabled, no aria-disabled, has handler). The S03.5 docblock's "S03.8 will remove `disabled` and bind the example-CSV click handler" promise is fulfilled.
- **S03.7 reducer compatibility.** The example-CSV handler dispatches `{ kind: 'drop', file: makeExampleFile() }` through `handleAccept`, which routes through the reducer. The reducer's drop branch (S03.7's typed shell) transitions `empty → active` with the synthesised File. The handler is identical in shape to a real drag-drop, so the reducer doesn't need to know whether the file came from the picker, drag-drop, paste, or example-CSV.
- **E08 fixture set.** `public/examples/sample.csv` is the same fixture E08 will use for golden tests. E08 reads the fixture directly (not via the generated module) so the golden tests don't depend on the build script running first.
- **Bundle determinism.** The generated module is deterministic (no timestamps in the output). Vite's hidden-source-map build produces a deterministic bundle hash per fixture version. The `npm run check:bundle` total is stable across runs.
- **No new network primitives.** `inline-example.mjs` uses Node's `fs` (filesystem reads, not network). `example-csv.ts` and `example-csv.generated.ts` are pure TypeScript. The deployed bundle carries no `fetch` paths.

## Out of scope for S03.8

- **More than one example CSV.** E08 may add additional fixtures for golden tests (e.g., malformed CSV, BOM-prefixed CSV, large CSV), but S03.8 ships ONE fixture.
- **UI for choosing among multiple examples.** S03.8 ships one "Try the example" button. A dropdown / carousel of examples lands later if at all.
- **Reading the file via streaming.** E06 S06.1.
- **Refusal-state UI for an example that's over-cap.** The example is small (under 4 KB) — it's well under the 50 MB cap. A regression that makes the example > 50 MB would trip the S03.3 cap gate; the AC24a size pin prevents this.
- **A different fixture format.** S03.8 ships CSV (the app's primary input). JSON / TSV / Excel support lands later if at all.
