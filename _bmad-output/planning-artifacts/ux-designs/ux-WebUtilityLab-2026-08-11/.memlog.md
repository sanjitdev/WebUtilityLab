- (decision) Form-factor resolved: C — desktop-primary, mobile not optimized. PRD §2.2/§5 mobile-as-non-audience holds. Layout adapts but does not chase parity. Touch targets meet minimum sizes (44x44 CSS px) as a courtesy floor; mobile polish is deferred.
- (decision) DESIGN.md.Brand & Style posture: Editorial / typography-led. References: gov.uk, stripe.com long-form, pioneer.app. Trust through seriousness; reads like documentation, not SaaS landing.
- (decision) DESIGN.md.Colors: Two-tone (light/dark) with semantic accents. Base palette per mode + 4-5 semantic colors mapped to problem categories (errors, warnings, PII, success, info). No decorative color; semantic only.
- (decision) DESIGN.md.Typography: Sans body (system stack — Privacy Baseline prohibits web fonts). Mono ONLY for data: CSV content, column names, schema types, file paths, score values, PII matches. Two-typeface system at most.
- (decision) DESIGN.md.Color mode strategy: both light + dark with system-preference detection and a manual toggle in the header. Manual override persists in localStorage (no account, no server). Toggle is a quiet icon (sun/moon), not a button with text.
- (decision) DESIGN.md.Color palette draft (subject to key-screen validation): Light = paper-white-warm base + ink-black primary + low-contrast graphite secondary + desaturated cobalt accent. Dark = deep-slate base (not pure black) + warm off-white primary + lower-contrast secondary + same cobalt accent. Semantic accents: red=error, amber=warning, blue=info, violet=PII (distinct category, not just an error), green=success (used sparingly, only for explicit success states). Outlier/duplicate use neutral (no color), communicated via typography treatment.
- (decision) DESIGN.md.Semantic categories (locked): error / warning / outlier / duplicate / PII / info / success. PII is its own category — distinct color (violet) so the eye learns to scan for it. Outlier and duplicate use neutral palette with typographic treatment (underline, strikethrough, weight) so color budget stays reserved for hard signals.
- (decision) IA: Single page, scroll-driven (option A). One HTML page; empty state morphs into active state which morphs into results via scroll/visibility. No routing. Privacy signal stays at top throughout. Note: focus management on state changes is a follow-up accessibility concern (will revisit at Finalize key-screen mocks).
- (decision) EXPERIENCE.md.Voice register: restrained spec. Short, declarative, near-vocabulary-of-the-domain. Editorial precision over warmth; trust comes from being exact, not conversational. Brief exemplar 'Trailing comma at line 14 — JSON does not allow trailing commas. Remove the comma after "name" and try again.' is the calibration target.
- (decision) EXPERIENCE.md.Typography conventions: curly quotes/apostrophes throughout prose; spaced em-dashes ('word — word'); sentence-case headings; mono for data values (CSV content, column names, PII matches) — data values keep their original straight quotes and casing unchanged. Editorial with terminal-cleanliness in data regions.
- (decision) EXPERIENCE.md.Empty state copy (locked draft): 'Drop a CSV to find out what's wrong with it. Files up to 50 MB, UTF-8, with or without a BOM. We don't upload — this happens in your browser. [Try the example] · [Browse files]'. Carries the JTBD sentence ('find out what's wrong with it') and the privacy signal in the same block.
- (decision) EXPERIENCE.md.Error message template (locked): strict brief pattern — '[specific finding] — [domain rule]. [concrete next action].' CSV Rescue-specific examples: 'Row 14 has 12 fields, expected 11 — your file uses commas inside quoted strings. Open row 14 in a text editor and check that any literal commas are wrapped in double quotes.' Pattern is testable: every error message must contain a specific finding (file, row, column, value), the rule that was broken (in domain terms), and a concrete next step (open file in editor / strip BOM / re-upload / etc.).
- (decision) EXPERIENCE.md.Results page structure: stacked vertical sections. Order: detected problems (top, primary), data-quality score (with category breakdown), inferred schema (column-by-column), cleaning CTA (bottom). Each section is its own card. Editorial reference: Stripe report layout. Scroll-driven per IA decision; results page never requires navigation.
- (decision) EXPERIENCE.md.Clean-and-Export flow: one CTA + modal. Primary button 'Clean and export' opens a modal with per-category toggles (dedupe, fill-missing, validate-and-flag, normalize-categorical, redact-PII). Default state: ALL toggles OFF — cleaning is opt-in, conservative default per FR-5. Modal includes a kind-error confirm for irreversible actions (PII redaction): 'Redacting PII replaces the original column values with [REDACTED] in the cleaned file. The original file is not retained — this cannot be undone.' Modal close on Esc, click outside, or Cancel; modal close on confirm.
- (decision) EXPERIENCE.md.Accessibility floor: WCAG 2.2 AA + keyboard-first. Color contrast 4.5:1 body / 3:1 large-or-UI. All interactions reachable via keyboard. Visible focus rings (2px solid cobalt accent, 2px offset). Skip-link at top: 'Skip to results' on results page. prefers-reduced-motion respected (no spinner animation if motion reduced; static 'Working…' text instead). aria-live='polite' regions announce state changes (file accepted, processing complete, cleaning complete). Semantic HTML throughout — no divs masquerading as buttons.
