Encoding error

We can’t read this file as UTF-8.

The file’s first three bytes are a UTF-8 BOM (0xEF 0xBB 0xBF) — but the bytes that follow aren’t valid UTF-8 text.

CSV Rescue requires UTF-8 because the data quality checks (email validation, date parsing) only work on Unicode text. Files that look like UTF-8 but aren’t usually got their encoding wrong at save time — most often this is Windows-1252 saved as UTF-8 by a misconfigured editor.

Open the file in a text editor that lets you pick the encoding on save — VS Code, Sublime, Notepad++ — and re-save it as UTF-8 (no BOM). Then drop it again.
