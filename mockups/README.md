# Key-Screen Mocks

Reference HTML mocks for the five key surfaces of CSV Rescue. These are **tracked artifacts** for the build — every component story in `epics.md` should reproduce the layout, semantic HTML, accessibility wiring, and visual tokens shown here.

## Files

| File | Surface | Anchors | Status |
|---|---|---|---|
| `key-screen-empty.html` | Initial empty state | AD-9 (skip-link, focus rings), AD-10 (editorial voice), AD-7 (theme) | final |
| `key-screen-results.html` | Results page (problems, score, schema, cleaning CTA) | AD-9, AD-10, AD-11 (mechanism-B links), AD-12 (schema shape) | final |
| `key-screen-modal.html` | Cleaning modal (5 toggles, reversibility view, Confirm/Cancel) | AD-6 (5 toggles ALL OFF, reversibility), AD-9 (focus trap) | final |
| `key-screen-refusal.html` | Refusal state (file too large for 10s budget) | FR-6 (10s budget), AD-5 (refusal state) | final |
| `key-screen-error.html` | Error state (UTF-8 encoding mismatch, malformed CSV) | AD-10 (strict-brief), AD-9 (focus, aria-live) | final |

## Conventions enforced

- **Theme tokens via CSS variable class flip on `<html>`** (AD-7). The mocks that use `<html class="dark">` (empty, results, modal) and `<html data-theme="dark">` (refusal, error) both render; the build will standardize on the class-flip pattern from the architecture spine.
- **Skip-link as the first focusable element** (AD-9). Targets `#main` on empty, `#modal-title` on modal, `#error` on error.
- **Focus rings:** `2px solid var(--accent); outline-offset: 2px` (AD-9).
- **Editorial voice:** curly quotes/apostrophes, spaced em-dashes, mono for data (AD-10). Mono data values retain their original straight quotes and casing.
- **Visual tokens:** all component CSS consumes `var(--*)` tokens (AD-8). The only hex literals are inside `:root` / `.dark` token blocks — the **source of truth**, not a violation.
- **No web fonts.** System UI stack only (Privacy Baseline).
- **No spinner.** Static "Working…" / "Building cleaned file…" text only.

## How to use these mocks

The build will:

1. Translate each HTML mock into the corresponding Svelte component (`Dropzone.svelte`, `Results.svelte`, `CleaningModal.svelte`, `RefusalState.svelte`, `ErrorState.svelte`).
2. Move the `:root` / `.dark` token blocks into `src/styles/tokens.css` (E02 S02.1).
3. Replace literal demo data (`name,email`, sample `123 Main St`) with the typed `Finding` / `Column` / `Score` envelopes from the worker.
4. Preserve the AD wiring: skip-link, focus rings, semantic HTML, theme class flip, no-font, no-fetch, no-network.

The mocks are not the source of truth for **visual style tokens** — `src/styles/tokens.css` (E02) is, derived from `DESIGN.md`. The mocks are the source of truth for **layout, semantic structure, and accessibility wiring**.

## What is NOT in the mocks

- Real CSV parsing (these are static previews).
- Real Web Worker (the actual analysis runs in E05–E09).
- The 12 detection categories' full data — the results mock shows a curated subset.
- Mechanism-A (file metadata handoff) — not a key-screen; deferred.
- Mechanism-D (PWA) — explicitly out of MVP scope.

## Updating a mock

If a layout, copy, or token change is needed before E10/E11/E12 lands:

1. Edit the mock here, not the `.working/` original. The `.working/` files are bmad-ux workflow artifacts and may be regenerated by future UX runs.
2. Update the corresponding `epics.md` story if the change crosses an AD boundary.
3. Log the change via `uv run _bmad/scripts/memlog.py append --workspace _bmad-output/planning-artifacts/epics-and-stories/epics-WebUtilityLab-2026-08-11 --type change --text "..."`.

## Privacy verification

Every mock, opened in a browser with DevTools Network tab recording, shows **zero network requests** after the local file load. The Privacy Baseline applies to the mocks as much as to the build.
